# CommerceGuard v0.3 Ops Pilot

Estado: operacion recurrente basica, no SaaS.

## Objetivo

Validar que CommerceGuard puede correr de forma recurrente, clasificar fallas y notificar sin generar ruido por falsos positivos.

## Core vs Adapter

- Core: `src/runner`, `src/config`, `src/evidence`, `src/reports`, `src/scheduler`, `src/notifications`.
- Adapter Car One: `recipes/car-one*.json`, `src/adapters/car-one`, `src/dev`, `configs/scheduler.car-one.*.json`.
- Multi-proyecto liviano: cada receta declara `projectId`, `adapter` y `reportGroup`.

## Scheduler

Prueba local una sola vez:

```powershell
pnpm.cmd run mock:car-one
pnpm.cmd run scheduler -- configs/scheduler.car-one.local.json --once
```

Prueba controlada de N ciclos:

```powershell
pnpm.cmd run scheduler -- configs/scheduler.car-one.local.json --cycles 3
```

Scheduler staging:

```powershell
$env:CARONE_BASE_URL="https://stg.carone.com.ar"
pnpm.cmd run scheduler -- configs/scheduler.car-one.staging.json
```

Webhook simple:

```powershell
$env:CARONE_BASE_URL="https://stg.carone.com.ar"
$env:CG_WEBHOOK_URL="https://example.com/webhook"
pnpm.cmd run scheduler -- configs/scheduler.car-one.staging.webhook.json
```

## Politica de alertas

Default recomendado:

- alertar por `COMMERCE_FAILURE` y `MONITOR_FAILURE`;
- no alertar por `INCONCLUSIVE` en la primera etapa;
- requerir 2 fallas consecutivas antes de notificar;
- notificar recovery cuando vuelve a `PASS`.

Lectura:

- `FAIL + FAIL`: incidente candidato.
- `FAIL + PASS`: intermitente, revisar evidencia pero no alertar fuerte.
- `INCONCLUSIVE`: evidencia insuficiente; no tratar como falla de comercio.

Validacion local de 2 fallas consecutivas:

```powershell
$env:CG_MOCK_MODE="BROKEN_CTA"
pnpm.cmd run mock:car-one
pnpm.cmd run scheduler -- configs/scheduler.car-one.local-alert-test.json --cycles 2
```

Esperado: la primera falla no notifica; la segunda emite una notificacion `stdout`.

## Stability staging

Muestra recomendada:

```powershell
$env:CARONE_BASE_URL="https://stg.carone.com.ar"
pnpm.cmd run run:repeat -- recipes/car-one.template.json --count 50
```

Si 50 corridas dan 0 `COMMERCE_FAILURE`, 0 `MONITOR_FAILURE`, baja o nula flakiness y pocos/no `INCONCLUSIVE`, avanzar a scheduler piloto.
